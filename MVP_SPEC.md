# MVP‑спецификация: агрегатор православных новостей

## 1. Продукт и цель

**Продукт:** Веб‑сайт (и Telegram‑канал) с единой лентой новостей по православию: РПЦ, Украина, Молдавия, Армения, Греция (включая Афон) и другие юрисдикции.

**Цель MVP:** Проверить гипотезу, что пользователям удобно читать новости из множества церковных источников в одной ленте с фильтрами, а не обходить сайты по отдельности.

**Однострочная формулировка:**  
「Одна страница, где за 1–2 минуты видно все важные православные новости за день по выбранным странам/юрисдикциям」.

## 2. Пользователь и проблема

**Основной пользователь:**
- Православный христианин (Россия, Украина, Молдавия, Греция, диаспора), 25–55 лет, регулярно интересуется церковными новостями.

**Проблема:**
- Новости разбросаны по десяткам сайтов (патриархаты, епархии, православные СМИ, общие новостные порталы).
- Нет удобной единой ленты с фильтрами по стране/юрисдикции.

## 3. Ядро продукта (core promise)

**v1 должен гарантировать:**

1. Показывать актуальную ленту новостей из 40–60 источников (РПЦ + Украина + Молдавия + Армения + Греция/Афон + другие).
2. Давать базовые фильтры:
   - по стране/юрисдикции (РПЦ, УПЦ, ПЦУ, Молдавия, Армения, Греция, Афон и др.);
   - по дате (сегодня / последние 3 дня / все);
   - по ключевому слову (поиск по заголовкам).
3. Открывать полную новость на сайте источника (агрегатор хранит только заголовок, краткий анонс и ссылку).

## 4. Основные пользовательские сценарии (user flows)

### Сценарий 1: 「Быстро посмотреть новости за день」

1. Пользователь заходит на главную страницу.
2. Видит ленту новостей за сегодня (по умолчанию — все источники).
3. При необходимости выбирает фильтр (например, 「РПЦ」, 「Украина」, 「Афон」).
4. Кликает на интересную новость → переходит на сайт источника.

**Критерий успеха:** пользователь за ≤2 минуты находит 3–5 релевантных новостей и переходит к оригиналам.

### Сценарий 2: 「Следить за конкретной юрисдикцией」

1. Пользователь выбирает фильтр 「Афон」, 「Армения」или 「Молдавия」.
2. Видит ленту только по этой юрисдикции.
3. Может сохранить ссылку на этот фильтр (закладка браузера).

**Критерий успеха:** фильтр корректно ограничивает ленту, без 「чужих」новостей.

### Сценарий 3: 「Получать дайджест в Telegram」

1. Пользователь подписывается на Telegram‑канал агрегатора.
2. Раз в день получает пост 「Топ‑10 новостей за день」с ссылками.
3. При желании переходит на сайт для более детального просмотра.

**Критерий успеха:** дайджест приходит стабильно, ссылки работают, посты читаемы на мобильном.

## 5. Функциональные требования (must‑have для MVP)

### 5.1. Сбор новостей

- Поддержка RSS/Atom и HTML‑лент новостей.
- Минимум 40 источников на старте.
- Автоматический опрос источников:
  - крупные — каждые 10–15 минут;
  - епархии/мелкие — раз в 30–60 минут.

### 5.2. Нормализация и хранение

Для каждой новости хранится:

- `title` — заголовок;
- `summary` — краткий анонс (1–3 предложения);
- `content_url` — ссылка на оригинал;
- `source_id`, `source_name` — идентификатор и название источника;
- `published_at` — дата публикации у источника;
- `jurisdiction` — юрисдикция;
- `country` — страна;
- `language` — язык (ru, uk, ro, hy, el, other).

### 5.3. Дедупликация

- Обязательная дедупликация по `content_url`.
- Базовая дедупликация по заголовку.

### 5.4. Веб‑сайт (фронтенд)

- Главная страница:
  - лента новостей (карточки: заголовок, дата, источник, краткий анонс, кнопка 「Читать далее」);
  - фильтры: юрисдикция, страна, дата, поиск по заголовку.
- Адаптивная вёрстка (мобильная + десктоп).

### 5.5. Telegram‑канал / бот

- Канал с ежедневным дайджестом:
  - заголовок 「Православные новости, [дата]」;
  - 8–12 новостей с короткими анонсами и ссылками.
- Автоматическая публикация раз в день (вечером).

### 5.6. Админка (минимальная)

- Список источников с полями: URL, тип (RSS/HTML), юрисдикция, страна, статус (активен/отключён).
- **Редактирование новостей:**
  - выключить/включить конкретную новость (`is_visible`);
  - отредактировать заголовок (`manual_title`);
  - отредактировать анонс (`manual_summary`).

## 6. Нефункциональные требования

- **Производительность:**
  - Главная страница загружается ≤2 с на 4G.
- **Надёжность:**
  - При падении парсера для одного источника остальные продолжают работать.
- **Безопасность:**
  - HTTPS обязательно.
- **Масштабируемость:**
  - Архитектура должна позволять легко добавлять новые источники.

## 7. Out of scope (что НЕ входит в v1)

- Личные кабинеты, регистрации, избранное, уведомления на email.
- Полнотекстовый поиск по содержимому статей (только по заголовкам в v1).
- Умная классификация 「мнение/новость/скандал」.
- Мобильное приложение.
- Платные подписки, реклама, монетизация.

## 8. Метрики успеха MVP

**Основная метрика (через 2–4 недели после запуска):**

- **Weekly Active Users (WAU)** на сайте ≥ 200 уникальных пользователей в неделю.

**Дополнительные метрики:**

- Среднее время на сайте ≥ 1:30 мин.
- CTR переходов на источники ≥ 20%.
- Подписчики Telegram‑канала ≥ 300 за первый месяц.
- Доля возвратов ≥ 25%.

## 9. Ограничения и риски

- **Юридические:**
  - Копирование полных текстов новостей может нарушать авторские права; в v1 храним только заголовки + короткие анонсы + ссылки.
- **Технические:**
  - Часть источников может не иметь RSS, менять структуру, вводить защиту от парсинга.
- **Контентные:**
  - Риск попадания откровенно пропагандистских/фейковых материалов; нужна базовая модерация.

## 10. Техническая реализация (кратко)

- **Бэкенд:** Python + Flask (или FastAPI), SQLite (для MVP) / PostgreSQL.
- **Парсинг:** feedparser (RSS/Atom), BeautifulSoup4/lxml (HTML).
- **Фронтенд:** лёгкий JS‑фреймворк (Vue 3 / Svelte), Vite.
- **Хранение и поиск:** SQLite / PostgreSQL + (опционально) Meilisearch.
- **Telegram:** aiogram/pyTelegramBotAPI.
- **Развёртывание:** один недорогой VPS или PaaS (Render / Railway / Fly.io).

## 11. План релиза

**Этапы:**

1. **Неделя 1–2:** Реализовать сбор с 40–50 источников, базовую ленту и фильтры. Закрытый тест.
2. **Неделя 3:** Добавить Telegram‑канал с дайджестом.
3. **Неделя 4:** Публичный запуск, сбор обратной связи.

## 12. Архитектура (схема)

```
[Источники: RSS/HTML] 
        ↓
[fetch_news.py] (парсер, дедупликация)
        ↓
[SQLite / PostgreSQL] (таблицы: sources, seen_items, items)
        ↓
[Flask API] 
   ├─ /api/news (лента для сайта)
   ├─ /api/admin/item (редактирование новостей)
   └─ /api/admin/source (управление источниками)
        ↓
[Фронтенд: Vue/Svelte] 
   ├─ Главная (лента + фильтры)
   └─ /admin (админка)
        ↓
[Telegram бот] (daily digest)
```

## 14. Справочник юрисдикций и стран

### 14.1. Что такое «юрисдикция」в этом документе

**Юрисдикция** — каноническая церковная структура (поместная церковь, патриархат, автокефальная/автономная церковь), которой подчиняется конкретный источник новостей (патриархия, епархия, монастырь, портал).

Это не то же самое, что страна:

- Одна страна может включать несколько юрисдикций (например, Греция: Элладская церковь + территории под Константинополем, включая Афон).
- Одна юрисдикция может присутствовать в нескольких странах (например, РПЦ в России, Молдавии, Казахстане, Прибалтике и др.).

### 14.2. Список юрисдикций для MVP

#### Основные (по вашему запросу)

- **ROC** — Русская православная церковь (Московский патриархат).  
  Включает епархии в России и других странах канонической территории МП.
- **UOC** — Украинская православная церковь (каноническая, в составе Московского патриархата).  
  Канонически часть ROC, но в агрегаторе выделяем отдельно из‑за новостной специфики.
- **OCU** — Православная церковь Украины (ПЦУ, автокефальная).  
  Отдельная юрисдикция, не в составе Московского патриархата.
- **Moldova_ROC** — Православная церковь Молдовы (в составе Московского патриархата).
- **Moldova_ROM** — Митрополия Бессарабии (в составе Румынской православной церкви).
- **Armenia** — Армянская апостольская церковь (древневосточная, но для агрегатора логично отдельная юрисдикция).

#### Греция и Афон

- **Greece_HOC** — Элладская православная церковь (Автокефальная церковь Греции).  
  Юрисдикция охватывает большую часть территории Греции.
- **Greece_CP** — Епархии в Греции, находящиеся под духовной юрисдикцией Константинопольского патриархата (например, Крит, Додеканес).
- **Athos** — Священная Гора Афон.  
  Автономное монашеское государство в составе Греции, **под духовной юрисдикцией Константинопольского патриархата**.  
  Для агрегатора удобно выделить Афон как отдельную юрисдикцию, потому что:
  - у Афона особое административное и духовное устройство (20 монастырей, собственный Священный Кинот);
  - новости часто идут именно в разрезе 「Афон / конкретный афонский монастырь」, а не 「Греция в целом」.

> Итого по Греции:  
> - `Greece_HOC` — основная церковь Греции;  
> - `Greece_CP` — греческие епархии Константинополя;  
> - `Athos` — Афон (духовно Константинополь, но тематически отдельная сущность).

#### Дополнительные (на будущее, можно добавить в том же формате)

- **Romania** — Румынская православная церковь.
- **Serbia** — Сербская православная церковь.
- **Bulgaria** — Болгарская православная церковь.
- **Georgia** — Грузинская православная церковь.
- **Antioch** — Антиохийская православная церковь.
- **Alexandria** — Александрийская православная церковь.
- **Jerusalem** — Иерусалимская православная церковь.
- **Constantinople** — Константинопольский патриархат (вселенский), кроме уже вынесенных в `Greece_CP` и `Athos`.
- **ROCOR** — Русская православная церковь за границей (сейчас часть ROC, но может выделяться в новостях).

#### Прочие

- **Other** — всё остальное (например, новости, где юрисдикция не указана или смешана).

### 14.4. Примеры соответствия 「источник → юрисдикция + страна」

- `patriarchia.ru` → `jurisdiction = ROC`, `country = RU`
- Епархия УПЦ (МП) в Украине → `jurisdiction = UOC`, `country = UA`
- Сайт ПЦУ → `jurisdiction = OCU`, `country = UA`
- Митрополия Молдовы (МП) → `jurisdiction = Moldova_ROC`, `country = MD`
- Митрополия Бессарабии → `jurisdiction = Moldova_ROM`, `country = MD`
- Католикосат всех армян (Эчмиадзин) → `jurisdiction = Armenia`, `country = AM`
- Официальный сайт Элладской церкви → `jurisdiction = Greece_HOC`, `country = GR`
- Сайт епархии Крита → `jurisdiction = Greece_CP`, `country = GR`
- Сайт афонского монастыря (например, Ватопед, Эсфигмен, Русский на Афоне) → `jurisdiction = Athos`, `country = GR`
